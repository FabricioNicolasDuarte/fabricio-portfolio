De las planillas del campo a un tablero de indicadores

En un establecimiento el peso de los animales, el clima, la condición corporal y los tratamientos suelen estar en Excel o en planillas de manga. Este proyecto toma esas planillas, las ordena y calcula cuatro números que importan en el día a día: cuánto gana el animal por día, cuántos hay por hectárea, cuánto calor de riesgo hubo y qué porcentaje está flaco.

Abajo está el tablero ya calculado. El código para repetirlo en una PC está en GitHub (Docker: Apache Airflow + PySpark). Si no hay cluster, Spark corre en la máquina.

Tablero (resultado publicado)

Qué ve alguien del campo

ADG — kilos que gana el animal por día, entre una pesada y la siguiente.

Carga — cuánta hacienda hay por hectárea útil (no un conteo de un solo día).

ITH — horas de calor en las que el ganado está en estrés (índice temperatura-humedad).

BCS — porcentaje de animales flacos (condición corporal menor a 4 en escala 1–9).

Qué ve alguien de datos

StackApache Airflow (DAG), PySpark, Delta Lake, Databricks Free Edition o Spark local[*], Streamlit, Docker Compose.
IngestaCSV de manga (;, dd/MM/yyyy). Corrección de pesada: mismo pesada_id, gana captured_at (MERGE).
BronzeDelta, overwrite de partición ingest_date. No se tiran filas sucias.
SilverContrato de rangos; cuarentena; late-arriving = captura > evento + 24 h.
QualityPK, nulos, BCS 1–9, ITH físico, tope de late-arriving. Si falla, no publica gold.
Gold ADGGap ≥ 7 días, clip (−1.2, 2.4) kg/d, exclusión en retiro sanitario.
CargaΣ UA-día / (ha útil × días), no cabezas/ha puntuales.
EscalaDAG skadia_medallion_ganaderia. Default 2 000 animales × 90 días. Dataset de demostración.

Correrlo en una PC

Hace falta Docker Desktop (~4 GB RAM). Databricks no es obligatorio.

git clone https://github.com/FabricioNicolasDuarte/skadia-data-engineering.git

cd skadia-data-engineering

docker compose up -d --build && docker compose run --rm pipeline run-all

Tablero local: http://localhost:8501 · Airflow: http://localhost:8088 (admin / admin)
